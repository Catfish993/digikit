## Corrections to the 2026-09-11 handover

1. **`FUN_4011d67a` never ran — it did not "run and fail".** Its guard is
   `FUN_4011d604` (Digitakt `FUN_4011fe60`, byte-identical), a ten-iteration
   GPIO continuity check on `0xEC09401A/1B` and `0xEC094027`. Unmodelled GPIO
   reads zero, so it returns 1 on its first pass. Identical in both builds.
2. **"Digitakt is on the correct display path" is unsupported.**
   `FUN_400d5c34` (Digitakt `FUN_400d39ec`) arms PIT3 for the *intro* in both
   images, so PIT3 firing proves nothing about `display_start`. Digitakt
   reached `display_start` only through a "Migrate presets" dispatcher case
   that Digitone's build does not contain, and that case fires *because* the
   SD struct is zeroed. It was an artifact, not a working path.

## What the fix was

Four real defects, all in models that existed (`emu/gpio.py` `SdGate`,
`emu/esdhc.py`) but that no caller had ever enabled:

1. Neither model was available on the cold-boot path. The guard runs at
   instruction **64,164,269**, before the first ladder rung at 60M, so
   enabling them only at resume is useless.
2. `DRV_STATUS` was hardcoded to Digitakt's `0x44E26F1C`; on Digitone every
   command reported "in progress" and CMD0 took the −1 exit.
3. `_dma_out` never set the TCD CSR DONE bit, so the closing CMD8 EXT_CSD
   read timed out and bailed silently.
4. Nothing posted the driver's completion semaphore, so the cold path blocked
   forever in `sem_pend`. `longrun`'s `unblock=True` hid this at resume.

Plus: `Esdhc` must `m.ensure()` its own pages — host-side `uc.mem_write` does
not enter `Machine._fault`, so construction died with `UC_ERR_WRITE_UNMAPPED`
on cold boot.

All per-image addresses now resolve through `emu/symbols.py`: `sd_bringup`,
`sd_flag`, `sd_status`, `sd_cmd_sem`, `sd_data_sem`.

## The SHARC DSP

Went from unreadable blob to disassembling in Ghidra.

- Section 7 is the DSP image. Only its first **11,248 bytes** parse as an ADI
  boot-stream (4 blocks), and that prologue is **byte-identical in both
  products** — a shared second-stage loader.
- **Not compressed.** Calibrated against this firmware's own aPLib streams
  (7.83–7.88 bits/byte); the payload regions measure 6.416 and 7.260.
- Encoding is **SHARC+ VISA**, 16-bit granular variable length. Repeated
  motifs land on even offsets 100% of the time but spread uniformly mod 4, 6
  and 8.
- **Addressing: 16-bit short-word units.** `(0x282403f0 − 0x28000000) / 2 ==
  0x1201f8`, exactly the loader's first cjump target.
- **ADI's compiler emits `cjump` (type 25a_direct), not `CALL`.** That is the
  call graph. Digitakt's 224 KB region: 1,656 call sites, **506 distinct
  functions**, 245 in `0x1cxxxx` and 261 in `0xb8xxxx`.
- **Ghidra disassembles it**: `tools/ghidra/SHARC` + `install-sharc.sh`.
  387 of 506 targets disassemble, 13,755 instructions.
- Region layout, self-consistent: two chunks at word bases `0xb80000` and
  `0x1c0000`, boundary constrained to file offset 189,796..195,668.
  Import at **byte** base `2 × word address`.

### Open DSP question

Which table is machine dispatch. Candidates are 100% indirect-only. The
**lead, not a finding**: Digitakt has an 11-entry ascending table at file
`0x0034fc`, and Digitakt exposes exactly 5 source machines + 6 filters = 11.
Digitone's structurally-parallel table at `0x003a94` has 6. Confirming needs
the code that *indexes* a table — the tables live in the earlier part of
section 7 whose load address is not yet mapped. Second route: `t9a`/`t9b` are
the register-indirect calls; where they cluster is the dispatcher.

## What is left, in the agreed order

1. **Input emulation — do this next.** There is *no* key/encoder/button
   support; grep finds none, and the only input path is `inq` (UART8
   MIDI/serial). You can boot and watch but cannot use the device, so a new
   feature can only be verified by reading memory. It is ColdFire-side, so
   fully emulatable and verifiable. Find how the panel is scanned (GPIO
   matrix / SPI / I-O expander) using `addrtrace` plus Ghidra. Cheap partial
   win first: `inq` already exists, and Elektron devices accept a lot over
   MIDI — some interaction may be drivable today.
2. **Container repacking** — hardware delivery.
3. **DSP p-code semantics.** Ghidra's p-code emulator can execute any
   language whose SLEIGH spec has semantics; ours has none (disassembly does
   not need them). Adding them incrementally makes the DSP *runnable*. End-to-
   end audio would also need DSPI2 modelled.
4. The DSP dispatch question above.

## Gotchas learned (all cost real time)

- **`wordsize=2` in SLEIGH silently matches nothing.** Ghidra loads the
  language, maps memory at the right addresses, and decodes zero
  instructions, with no diagnostic. Use a byte space and double targets.
- **SLEIGH mnemonics may not start with a digit**, and a token's `_all` field
  may only be a display operand when that word is otherwise unconstrained.
- **Ghidra recompiles the `.slaspec` at load**, so the `.sla` is a build
  artifact (gitignored).
- **Read PDF bit diagrams at 400 DPI cropped** (`pdftoppm -r 400 -x -y -W -H`),
  never whole pages — whole-page reads downscale the bit cells into
  illegibility and produced a wrong Type 8a layout twice.
- **`www.analog.com` refuses non-browser clients** (HTTP/2 INTERNAL_ERROR,
  then zero bytes over HTTP/1.1). `download.analog.com` works but hosts no
  processor manuals. The two PDFs in `docs/refs/` came from a third-party
  mirror and are **not checksummed against ADI's originals**.
- **The 59-test suite does not exercise the resume path** — the 5 skips are
  the real emulation tests, env-gated (`DT2_LONGRUN_SLC_REAL=1` etc.). "Tests
  pass" is weak evidence here; use `bootcheck --verify`.
- **The vendor DSP toolchain is Windows/Linux only**, with no macOS build.
  Not needed: the encoding tables are in the freely downloadable programming
  reference.

## Guardrails (carried forward, still in force)

- Evidence before emulation behaviour; do not invent registers or magic
  return values.
- Preserve checkpoint and firmware hash/manifest checks.
- Production execution may be subdivided only at timer deadlines.
- No TB flushing, `srtrap`, weak-pointer bypasses or branch forcing as
  production fixes.
- Never compare an address across builds; resolve through `emu/symbols.py`.
