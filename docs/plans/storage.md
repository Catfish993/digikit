# Storage: a large digikit store, samples on both devices (F2, 2026-10-22)

Status: done in the emulator (steps 1 to 7) on lane `tasks-images`, one commit per step; the open points below need Em's real devices. Rules: device facts only in `devices/*.toml` and `devices/ports`; new module and runtime code is Rust (no new C); Python only for
reverse engineering and dev tooling, the app starts no process; pre-1.0, so no migrations (existing modules are lost on a reflash and installed again).

Facts: `docs/findings/59-storage-regions.md`, `docs/MIDI-SYSEX-RPC.md` section 12.

## Design

- **Store format v3** in a per-device area from `[card.store]`: DT2 `0x2DF1000..0x2E1A000` (82 MiB), DN2 `0x800000` to the card end (about 22 GiB). Folders `modules/` and `samples/`. The old area
  `0x38000..0x3E000` retires everywhere (profiles, runtime, builder, reader, exporter, mirror, docs). Needs: folders (paths with `/`, listed per folder), reusable space (allocate into gaps), paths of at least 160
  bytes, more entries, streaming upload of large files (DATA chunks go to the card, not staged whole). Kept: copy-on-commit table and headers, power-cut safety, sha256 per file and VERIFY, the module load staging
  limit (64 KiB).
- **Runtime 0.3.0**: checks at boot that the card capacity covers the area; if not there is no store, it logs that and the boot goes on.
- **DT2 samples** go to the +Drive through the stock MidiRpc file commands (TS client, over the existing transports); the host converts WAV to the native file (the converter of `packages/emulator/plusdrive`
  compiled to wasm). **DN2 samples** go to the store's `samples/` folder, in the same native format, so a later sampling engine reads one format on both devices (the DN2 firmware cannot play them yet).
- **Workbench:** Transfer gets Modules and Samples, the same on both devices; the device layer picks the backend from the profile (`[storage] modules = "digikit"`, `samples = "stock-rpc" | "digikit"`).
  The Card panel and the mirror cover the new area (`plus_drive/<device>/digikit/...`).

## Needs Em's real devices

Nothing in this plan has run on a real device. In the order of risk:

1. **eMMC capacity per device.** The areas assume 0x2E1A000 sectors on both cards (the whitelist's 32 GB part). Read the real capacity (the stock `StorageSpace` reply or EXT_CSD SEC_COUNT) on a DT2 and a DN2. A smaller card gives "too small" and no store, never a write.
2. **The store area reads blank.** Both areas are assumed untouched by the stock firmware (finding 59 reads, no card write-watch on a used device). Read `[card.store]` through `dk:store` or a block read on a card that has been in use: the first sectors, both headers, the selection pair, must be all 0x00 or all 0xFF, or the runtime calls the card foreign and writes nothing (ABOUT says so).
3. **Where the DT2 factory samples and the +Drive end.** The DT2 area starts at 0x2DF1000, 0xE80 sectors after the +Drive's end at 0x2DF0180 (finding 59). Check on a device with a full +Drive that the allocator stops at page 0xA0080 as read, and that the factory table at 0x458000 is as described.
4. **The DT2 sample browser lists an uploaded file.** In the emulator ReadDir and the card show the file; on the device open the sample browser, find `/<folder>/<name>`, play it. Also that the firmware's close writes zeros as the 16-byte trailer (the host's verify assumes it; a different trailer makes every verify fail and the fallback is a read-back, which `ReadFileV1` does not give).
5. **MidiRpc chunk size on real USB.** The client's chunk size comes from the emulator runs; a real USB host stack and the firmware's MIDI buffer may need a smaller one. Time a 5 MB upload (the emulator: 51 s upload, 16 s verify on the DN2).
6. **A real DN2 does not play the stored samples.** That is by design (no sampling engine yet); check that the files in `samples/` do not disturb the stock UI, and that a FORMAT keeps the area (finding 59 reads that it trims to 0x457FFF).
7. **A real card's +Drive trailer** after a firmware save of a file written over MidiRpc: zeros or not (as in 4).
8. **Mixed use.** A project save, a firmware update and a stock Elektron Transfer session with a populated store: no sector of the area changes (the emulator's write-watch says none; confirm with `dk:store` hashes before and after).
